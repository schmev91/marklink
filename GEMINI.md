# MarkLink — Project Context & Instructions

MarkLink is a high-performance, static editor for **Markdown**, **JSON**, and **CSV**, featuring live previews, Mermaid diagram support, and URL-based sharing with zero cloud storage.

## Project Overview

- **Type:** Static Web Application (Vanilla HTML/CSS/JS)
- **Primary Goal:** Provide a private, client-side editor where all data persists only in the URL or local browser state.
- **Key Technologies:**
  - **Markdown Parsing:** [marked.js](https://marked.js.org/)
  - **Syntax Highlighting:** [highlight.js](https://highlightjs.org/)
  - **Diagrams:** [mermaid.js](https://mermaid.js.org/)
  - **URL Compression:** [lz-string](https://pieroxy.net/blog/pages/lz-string/)
  - **Styling:** Custom CSS with CSS Variables for Light/Dark modes.

## Architecture

The project is structured into three distinct modes, each with its own entry point and corresponding logic modules.

### Entry Points
- `index.html`: Markdown editor (default mode).
- `json.html`: JSON tree and node viewer.
- `csv.html`: Interactive CSV table with sorting and filtering.

### JavaScript Modules (`/js/`)
Modules use a standard IIFE-based pattern for encapsulation.

| Module Type | Markdown | JSON | CSV |
| :--- | :--- | :--- | :--- |
| **Orchestration** | `app.js` | `json-app.js` | `csv-app.js` |
| **Editor Logic** | `editor.js` | `json-editor.js` | `csv-editor.js` |
| **Preview/Render** | `preview.js` | `json-preview.js` | `csv-preview.js` |
| **Sharing Logic** | `share.js` | `json-share.js` | `csv-share.js` |

**Shared Modules:**
- `theme.js`: Manages light/dark mode preference and persistence.
- `splitter.js`: Handles the resizable vertical/horizontal panels.

### Styling (`/css/`)
- `style.css`: A comprehensive design system using CSS Custom Properties (`--bg-primary`, `--accent`, etc.). It handles responsiveness, theming, and specific styles for all three modes.

## Development Workflow

### Building and Running
This project has **no build step** and **no package manager**. All dependencies are loaded via CDN.

- **Serve Locally:** Use any static file server.
  - `python3 -m http.server 8000`
  - `npx serve .`
  - Or simply open `index.html` in a modern browser.
- **Port:** Default for Python is `8000`.

### Testing and Validation
- **Manual Testing:** Core features must be verified in a browser:
  - Markdown: Toolbar actions, Mermaid rendering, code highlighting.
  - JSON: Tree expansion, search, validation, card view.
  - CSV: Sorting headers, column filters, column visibility, CSV-to-JSON conversion.
  - Shared: Theme toggling, panel resizing, URL generation/loading.
- **Automated Tests:** None currently implemented.

## Development Conventions

1.  **Vanilla JS Only:** Maintain the zero-dependency (other than CDNs) philosophy. Do not introduce build tools or frameworks unless explicitly requested.
2.  **IIFE Encapsulation:** All new JavaScript modules should follow the `const ModuleName = (() => { ... return { publicMethods }; })();` pattern.
3.  **Theming:** Use CSS variables defined in `:root` and `[data-theme="dark"]` for all styling. Never hardcode colors in specific classes.
4.  **Accessibility:** Ensure toolbar buttons have `aria-label` or `data-tooltip` for clarity.
5.  **State Management:** Data is managed primarily through the DOM and URL hashes. Shared links are generated by compressing the editor's content using `LZString.compressToEncodedURIComponent`.

## Common Tasks

- **Adding a Toolbar Button:** Update the HTML in the relevant `.html` file and wire the logic in the corresponding `*-editor.js` or `*-app.js`.
- **Modifying Theme Colors:** Edit the `:root` variables in `css/style.css`.
- **Changing Markdown Behavior:** Adjust the `marked.setOptions` configuration in `js/preview.js`.
